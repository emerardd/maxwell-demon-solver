# Maxwell's puzzling demon 求解器

给解谜游戏 *Maxwell's puzzling demon* 做的关卡解析器、规则模拟器和求解器。目前覆盖 w1、w2 的机制（推动、热交换、粘性面、透明块），以及最基本的进入/退出关卡。

## 文件

| 文件 | 作用 |
|---|---|
| `mxw.py` | 解析 `world/*.mxw` 关卡文件和 `structure.json`（1149/1153 个文件可完整解析） |
| `sim.py` | 规则模拟器：走动、推动、粘连、热交换、胜负 |
| `solver.py` | A* 求解器（热惰性走步折叠、进入关卡块、时间预算、加权 A*） |
| `prune.py` | 静态推动距离表：A* 的启发值 + 死局剪枝 |
| `test_sim.py` | 规则单元测试，按 w1/w2 教程文本分组 |
| `run_world.py` | 批量求解一个世界的全部关卡，并在模拟器里回放验证 |
| `mxw_show.py` / `mxw_tree.py` / `w1_levelblocks.py` | 查看关卡网格、关卡树、关卡块 |
| `prof_solver.py` | 对单关做性能分析 |
| `mxw_probe.py` 等 `mxw_*.py` | 逆向格式时用的探查脚本 |

## 用法

日常验证用单元测试就够了，约 20 秒：45 个规则测试，加上解析覆盖率检查，以及 w1、w2 全部教程关的求解与回放。

```bash
python -m unittest test_sim
```

不设 `MXW_GAME_DIR` 时只跑规则测试，不到 1 秒。已知很慢的教程关（目前只有 `eadb3d02`）列在 `test_sim.GameData.KNOWN_SLOW` 里，单元测试会跳过它们。批量求解很耗时，只在需要时再跑：

```bash
python -u run_world.py "D:\Program Files (x86)\Steam\steamapps\common\Maxwell's puzzling demon" w2 cell 60
```

参数依次是：游戏目录、世界（`w1`、`w2` 或世界关卡 id）、热量计数口径（`cell` 每格 / `body` 每个刚体）、每关秒数、可选的关卡 id 列表。设置环境变量 `MXW_GAME_DIR` 后，`test_sim` 也会跑游戏数据测试（w1、w2 的全部教程关）。

## .mxw 格式

```
u8 W, u8 H
W*H 个格子对象（按行）
尾部: u8 目标数, 目标 (i8 x, i8 y)...;  { 02 x y 文本键\0 }...;  00
```

| tag | 对象 |
|---|---|
| `00` | 空 |
| `01` | 恶魔起点 |
| `02 attr sides` | 方块 |
| `03 flag id\0 未解对象 已解对象` | 关卡块 |
| `04 state 机身 优先级 [活动面]` | 活塞；state bit0=0（伸出）时才有活动面对象 |
| `05 attr sides x` | 活塞头的变体（含义待查） |

- **attr**：bit0 固定钉，bit1 储热（0 = 透明），bit2 热，bit3 冷，bit2+bit3 = 第四温度
- **sides**：每面 2 位，顺序 左、下、右、上；0 = 粘性（导热），1 = 导热，2 = 绝热。墙体和多格方块内部就是两两相对的粘性面
- 由网格边界相连的固定墙体代表"外界"，带导热面的墙格就是通向外界的窗口

## w1 求解结果（每关 90 秒：最优 A* 30 秒，超时后加权 A* 60 秒）

| 口径 | 解出并回放通过 | 无解 | 超时 |
|---|---|---|---|
| `cell`（按格） | 53/63 | 0 | 10 |
| `body`（按刚体） | 53/63 | 2（提示关 `cde27355`、`31a6bcbf`） | 8 |

按格计数时超时的关：`0f029258`、`4b1153be`、`a81d725f`、`00c134fe`、`32dce6a9`、`900ca6ab`、`b25aa619`、`85ad3cb0`、`eadb3d02`、`46c72163`。另外 `f9ab0810` 是加权 A* 解出的（`OK~`），不保证最短。这些关需要很长的推动序列，纯 Python 的搜索在时限内跑不完。下一步可以考虑：
- 死锁剪枝：比如推进角落、且不在目标上、旁边也没有窗口的方块就判死；
- 更强的启发：考虑"要先冷却热块才能推它"这类前置条件；
- 把搜索核心换成更快的语言。

完整日志在 `logs/w1_cell.log` 和 `logs/w1_body.log`。加上 `prune.py` 后重跑这 11 关（`logs/w1_hard.log`），只有 `f9ab0810` 变成了最优解（22.8 秒），其余 10 关仍然超时。这些关难在"先处理温度再推动"，按推动距离算的启发值看不出这一点。

## w2 求解结果（同样的时间预算，`logs/w2_cell.log`）

60 关里 42 关解出并回放通过（其中 `3b80a1f9` 是加权 A* 解出的），16 关超时。另外两关：
- `d07f4968` 含有带活塞的子关卡（w4 机制）。现在把这种子关卡当成"能进能出、但解不开"，父关卡照常搜索，只是还没在时限内解出。
- `a7674929` 在游戏里进不去。`structure.json` 里挂在提示关下面的子关条目共 360 个，其中 359 个都是父提示关地图上真实摆着的关卡块（走过去进入，不是按 H）。只有它是例外：它挂在 `7dc8d0b7`（w2 第 14 关 `3b80a1f9` 的提示关）下面，但全游戏没有任何关卡放着它的关卡块。它本身是个只有恶魔和目标、四面墙全导热的空房间，大概是遗留的废弃数据。`run_world.py` 现在会跳过这种找不到入口的关（用 `mxw_nested_hints.py` 可以复查），所以 w2 按 59 关计。

w2 的 5 个教程关全部解出，包括 `sticky-1`（之前被剪枝误杀，已修复）和 `sticky-2`（13.3 秒）。

## 已由关卡数据确认的规则

- **热量按格计数**：多格刚体有几格就算几份热量。依据是提示关 `cde27355`：恶魔要靠一根 2 格冷条去抵消 2 份热量（热块加上已被它烫热的中性块），全部打平成中性后才能把热块推上目标格。按刚体计数时这关无解。
- **侧面码 0 是粘性面**：`w2/sticky-1` 里有只有一面是 0、且这一面朝着空格的单个方块。粘性面碰到任何面（墙也算）就粘住，之后作为一个刚体移动，不会再分开；粘性面导热，但碰上绝热面不导热；恶魔不会被粘住。
- **透明块**（attr bit1 = 0）：不储热，热量份数为 0，压在目标格上不算过关。文件里有带温度的透明块（`B455`、`B855`），那只是它当前导过来的温度；它孤立时温度归零。

## 剪枝（prune.py）

在只保留墙体和固定方块的静态关卡里，从目标格反向 BFS，算出每个可能上目标的方块从各个位置最少要推几次。
- 作为 A* 的启发值。它忽略其他方块和温度，所以是可采纳的。
- 所有候选方块都到不了目标时，直接判死。
- 进关卡再退出会把所有物体恢复原位，所以启发值还要和"1 + 初始局面的距离"取较小值。
- 关卡里有带粘性面的可动方块时，几块可能粘成新形状、从任意一格推，这时改用宽松的距离表（只要求沿空格可达）。`w2/sticky-1` 就是这种情况。
- 已经粘死在墙上、又不在目标上的方块，不再算作候选。

## 规则模型里的假设（待在游戏里核对）

- 退出关卡时，恶魔出现在关卡块**初始位置**的旁边（w1 里分辨不出，w3 才能验证）
- 恶魔同时贴着多个关卡块时，求解器允许任选一个进入（游戏里是进编号最小的那个）
