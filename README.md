# Maxwell's puzzling demon 求解器

给解谜游戏 *Maxwell's puzzling demon* 做的关卡解析器、规则模拟器和求解器。目前覆盖 w1 到 w3 的机制：推动、热交换、粘性面、透明块，以及关卡的进入、退出和嵌套。

## 文件

| 文件 | 作用 |
|---|---|
| `mxw.py` | 解析 `world/*.mxw` 关卡文件和 `structure.json`（1149/1153 个文件可完整解析） |
| `sim.py` | 单个关卡内的规则：走动、推动、粘连、销毁、热交换、胜负 |
| `world.py` | 关卡之间的规则（w3）：进入路径、进出关卡、重置、外界温度 |
| `solver.py` | A* 求解器（热惰性走步折叠、路径深度迭代加深、时间预算、加权 A*） |
| `prune.py` | 静态推动距离表：A* 的启发值 + 死局剪枝 |
| `test_sim.py` | 规则单元测试，按 w1–w3 教程文本分组；外加游戏数据测试 |
| `run_tutorials.py` | 只求解一个世界的教程关，改完规则后快速检查用 |
| `run_world.py` | 批量求解一个世界的全部关卡，并在模拟器里回放验证 |
| `trace_plan.py` | 求解单关，并逐步打印解法每一步之后的局面 |
| `mxw_show.py` / `mxw_tree.py` / `mxw_nested_hints.py` / `w1_levelblocks.py` | 查看关卡网格、关卡树、提示关下的子关、关卡块 |
| `prof_solver.py` | 对单关做性能分析 |
| `mxw_probe.py` 等其余 `mxw_*.py` | 逆向格式时用的探查脚本 |

## 用法

日常验证用单元测试就够了：规则测试，加上解析覆盖率检查，以及 w1–w3 教程关的求解与回放。

```bash
python -m unittest test_sim
```

设了 `MXW_GAME_DIR` 时全部跑完约 40 秒；不设时只跑规则测试，不到 1 秒。`test_sim.GameData` 里有三份名单：
- `KNOWN_SLOW`：当前搜索在时限内解不完的教程关，单元测试跳过它们；
- `UNRESOLVED`：按现在的规则无解、还没弄清原因的教程关（目前是 3 个 `w3/path` 关）；
- `CONTEXT`：只能在特定上下文里解的教程关（需要先解开别的关、从冷/热关卡块进入，或者只会在上一级关卡里遇到）。单元测试会带着那个上下文去解，并检查它单独解时确实无解。

`Solver.solve(..., scope=上一级关卡)` 表示从上一级关卡开始搜索，直到目标关卡被解开为止。

改完规则后想看某个世界的教程关整体情况：

```bash
python -u run_tutorials.py "D:\Program Files (x86)\Steam\steamapps\common\Maxwell's puzzling demon" w3 15
```

批量求解很耗时，只在需要时再跑：

```bash
python -u run_world.py "D:\Program Files (x86)\Steam\steamapps\common\Maxwell's puzzling demon" w2 cell 60
```

参数依次是：游戏目录、世界（`w1`、`w2`、`w3` 或世界关卡 id）、热量计数口径、每关秒数、可选的关卡 id 列表。热量计数口径已确认是 `cell`（按格）。可动的多格方块现在按格拆成单独的物体，所以 `body` 口径已经不能复现当初那次对比实验了。

## .mxw 格式

```
u8 W, u8 H
W*H 个格子对象（按行）
尾部: u8 目标数, 目标 (i8 x, i8 y)...;  { 02 x y 文本键\0 }...;  00
```

| tag | 对象 |
|---|---|
| `00` | 空 |
| `01` | 恶魔起点 |
| `02 attr sides` | 方块 |
| `03 flag id\0 未解对象 已解对象` | 关卡块 |
| `04 state 机身 优先级 [活动面]` | 活塞；state bit0=0（伸出）时才有活动面对象 |
| `05 attr sides x` | 活塞头的变体（含义待查） |

- **attr**：bit0 固定钉，bit1 储热（0 = 透明），bit2 热，bit3 冷，bit2+bit3 = 第四温度
- **sides**：每面 2 位，顺序 左、下、右、上；0 = 粘性（导热），1 = 导热，2 = 绝热。墙体和多格方块内部就是两两相对的粘性面
- 由网格边界相连的固定墙体代表"外界"，带导热面的墙格就是通向外界的窗口

## 已由关卡数据确认的规则

- **热量按格计数**：多格刚体有几格就算几份热量。依据是提示关 `cde27355`：恶魔要靠一根 2 格冷条去抵消 2 份热量（热块加上已被它烫热的中性块），全部打平成中性后才能把热块推上目标格。按刚体计数时这关无解。
- **侧面码 0 是粘性面**：`w2/sticky-1` 里有只有一面是 0、且这一面朝着空格的单个方块。粘性面碰到任何面（墙也算）就粘住，之后作为一个刚体移动，不会再分开；粘性面导热，但碰上绝热面不导热；恶魔不会被粘住。
- **透明块**（attr bit1 = 0）：不储热，热量份数为 0，压在目标格上不算过关。文件里有带温度的透明块（`B455`、`B855`），那只是它当前导过来的温度；它孤立时温度归零。

## 关卡之间的规则（world.py，依据 w3 教程文本）

**真关卡块和捷径**：关卡块的标志位为 1 时，是这个关卡的**真关卡块**，放在它的真实上一级关卡里，游戏里显示为"1"这样的编号；标志位为 0 时是**捷径**，显示为"3-1"这样的编号。数据核对结果：901 个真关卡块全部放在 `structure.json` 给出的上一级里（`mxw_real_blocks.py`）。游戏内实测：不管从哪种关卡块、从哪个方向进入，按 Q 退出都会从真关卡块对应的那一侧出来。所以进入路径始终是**真实上级链**：进入关卡 X 时，路径变成从正在求解的关卡一路往下到 X 的真实上级链，原来就在路径上的层保持不变，中途跳过的层把这次进入的方向记作它们的进入方向。

搜索状态是整个"进入路径"：已解关卡集合；路径上每一层的关卡、外界温度、进入方向、入口关卡块；当前关卡的局面；以及中途离开、尚未重置的其他关卡的局面。

| 规则 | 实现 |
|---|---|
| exit-1 退出（解开或主动退出）时所有关卡重置 | 退回下一层，那一层恢复初始局面，保存的局面全部清空 |
| exit-2「离开关卡的位置和进入时相同」 | 恶魔回到它（最后一次）进入时站的那一格，也就是入口关卡块初始位置的进入侧 |
| enter-2 进入自己所在的关卡，局面延续 | 真实上级链不变，只更新这一层的进入方向和外界温度；恶魔回到起点 |
| 通过捷径进入路径上更低处的关卡（游戏内实测） | 路径截回到那个关卡的真实上级链 |
| enter-3 为了进入别的关卡而离开的关卡，在退出前保持局面 | 离开时保存它的局面，再进去时恢复 |
| transition-1 进出的那一刻不传热 | 恶魔出现时完全不做热交换：恶魔贴着热块或冷块不会立刻变温，方块之间也不换热（退出后上一层回到初始局面，即使初始局面里有冷热方块相贴，也不换热），全部留到下一次移动再结算。和游戏内体验一致 |
| transition-2 恶魔出现的位置上有方块，就把它销毁 | 进入和退出都会销毁；只销毁那一格方块，粘在一起的其余部分照常保留。**墙格也会被销毁，带钉的也一样**（游戏内实测，`w3/path`）：变成一个洞，恶魔可以站进去，方块也能推进去，洞四周的墙面照旧（大多是粘性面，所以推进去的方块会粘在墙上） |
| transition-3 进入时外界温度等于所进关卡块的温度；退出后所在关卡外界变中性 | 每层路径各记一个外界温度 |
| goal 解开关卡立刻自动退出 | 走完那一步就退回下一层 |

为了支持"只销毁一格"，可动的多格方块在模型里按格拆成单独的物体，由粘连分组连在一起。含有固定格的整块（墙体里有带钉和不带钉的格子）仍然合成一个物体。

路径上不会出现重复的关卡，所以路径长度最多等于不同关卡的个数。搜索仍按路径深度迭代加深：先只允许 2 层，再放宽到 3、4、6 层。如果深度上限从来没有挡住过任何一次进入，就直接判定无解，不再往下加深。

**两条规则是从游戏里纠正过来的。** 最初我按英文提示把 exit-2 理解成"沿进入方向从关卡块另一侧穿出来"，也让路径在循环进入时一直往下加层。后来在游戏里做了实验：提示关 → A（`1bfecdfb`）→ B（`b0e93052`），在 B 里再进入 A 然后按 Q，结果直接退到了 A 关外面。再加上中文提示「小麦克斯韦妖离开关卡的位置和进入时相同」，这两处都按实际行为改了过来。用 `where_is.py` 可以把内部 id 换成游戏里的位置描述。

**w3 教程关**：23 关全部解出并回放通过。其中 4 关只在上下文里解：
- `8d2fdcfc`：要先解开 `394c69e4`，再从 `44efd75a` 里那个冷的关卡块进入；
- `b0e93052`：只在它上一级 `1bfecdfb` 里遇到，要借助那里的关卡块；
- `w3/path` 的第 2、3 关（`9de258d5`、`601b40f2`）：从第 1 关 `0d33f295` 开始搜索。

**`w3/path` 三关的解法在游戏里实测过**，和求解器的解法一步步对得上：进 1 关、2 关、3 关 → 在 3 关里把通往 2 关的捷径推到最右边 → 通过它进 2 关、再进 3 关 → 解开 3 关 → 进 3 关，从右边进入通往 2 关的捷径，按 Q：恶魔出现在 1 关里 2 关真关卡块的右侧，也就是墙里，把墙打穿，进入原本封闭的小房间 → 在小房间里从右边进入通往 3 关的捷径，按 Q：恶魔出现在 2 关里 3 关真关卡块的右侧，把它往左推上目标，解开 2 关 → 从下面进入通往 3 关的捷径，按 Q、Q，回到 1 关 2 关真关卡块的下方，往上推三格，解开 1 关。

## 剪枝（prune.py）

在只保留墙体和固定方块的静态关卡里，从目标格反向 BFS，算出每个可动的粘连分组从各个位置最少要推几次，才能把它的一个不透明格压上目标。
- 作为 A* 的启发值。它忽略其他方块和温度，所以是可采纳的。
- 所有分组都到不了目标时，直接判死。
- 分组会变：粘连会合并分组，销毁会拆开分组。成员和初始时完全一样的分组用自己的距离表；变过的分组改用宽松的逐格距离表（只要求沿空格可达）。
- 关卡里有能粘上新东西的粘性面时，分组的距离表也用宽松算法。`w2/sticky-1` 就是这种情况。
- 已经粘死在墙上、又不在目标上的分组，不再算作候选。
- 关卡里有关卡块时，启发值最多取 1。因为进出关卡会重置局面，重新进入本关会让恶魔回到起点，解开关卡还会改变关卡块的属性，这些距离表都算不到。

## 不求最短解的引导式搜索

难关的开销全花在"不同的方块布局"上（`search_stats.py`）：恶魔位置折叠后，每种布局平均只剩约 1 个恶魔位置，但每多推一步，布局数就乘约 5 倍。可靠的剪枝最多只能省常数倍，比如相同方块互换位置的去重。所以在不需要最短解的场合，改用带引导的搜索：

- `heuristic='informed'`（`prune.Pruner.informed`，不可采纳）：对每个候选方块，取它沿距离表到目标的推动次数，再加上这些代价：
  - 路线上每有一个挡路的可动方块，就加罚分；
  - 路线上每个推动位置，如果会让恶魔贴到热块的导热面（包括候选方块自己），就算一个"危险源"，每个危险源加罚分，再加上最近的冷块到它的步行距离。这样把冷块运过去的局面会得到奖励。
- `solver.solve_any`：先用引导式搜索（权重 3）跑一半时间，超时后再用最短解 A*。引导式在温度类难关上快很多；但在嵌套关卡里它看不到方向，那里还是 A* 更好。单元测试和 `show_solution.py` 都用它。

小规模对比（`bench.py`，每次 45 秒，日志 `logs/bench_hard*.log`）：

| 关卡 | 原启发值 + 贪心 | 引导式，权重 3 |
|---|---|---|
| `0f029258` | 22.8 秒，84 步 | 29.5 秒，78 步 |
| `eadb3d02` | 超时 | **2.1 秒，24 步** |
| `4b1153be` | 超时 | 超时 |

之后又加了"冷却代价"：危险源的代价按冷源估算，已经是冷的方块按"到危险源的距离"计，可冻成冷的中性导热块按"到冷源的距离 + 冷源到危险源的距离 + 冻结代价"计，冷的份数不够抵消热时再加罚分。

`4b1153be`（w1 第 15 关）还没解出。它比看上去复杂：中间那个 2×2 其实是 4 个独立的方块，每个只有两个相邻的面导热（都朝 2×2 内侧），另外两面绝热。冷源只有左上凹槽里推不动的 1 格冷块，而目标下方恶魔要站的格子压在 4 格热条上。看样子要把这 4 个方块拆开，一个个贴着冷源冻冷，再按各自的导热方向拼到热条上，让恶魔所在的导热分量里至少有 4 份冷。这是一道"按导热方向接线"的题，单靠调启发值的参数攻不下来。另外试过"推动前要站的格子也检查危险"，结果让 `eadb3d02` 重新超时，已撤回。

## 分阶段的子目标搜索（腾挪关）

像 w1 第 15 关（`4b1153be`）这种腾挪关，必须先把最后几步的布局定下来，否则不管怎么调启发值，正向搜索都只会在海量布局里打转。`subgoal.py` 按顺序给出若干中间布局（某个方块要到哪一格、是否必须是冷的），用 `/` 分隔各阶段，逐阶段求解，最后再接着搜到过关：

```bash
python -u subgoal.py "<游戏目录>" 4b1153be 30 6@8,2:C / 2@7,2:C / 3@8,3:C / 5@7,3:C --out solutions/w1-15_4b1153be.txt
```

- 每个阶段都要保持前面阶段已经达成的部分，只再多放一块；
- 启发值是各方块到目标格的**推动距离**（反向搜索，并要求每一推的身后都有恶魔能站的格子，推进死角的方块距离为无穷大）；还没冻冷的方块，要绕道一个冻冷点，而且那个点必须推得进去、也推得出来；
- 冻冷点包括"恶魔站在中间当中转"的情况，恶魔导热但不储热；
- 后面阶段要用的方块，一旦被推到再也到不了目标的位置，就直接剪掉；
- 求解器为此新增了三个钩子：`Solver.solve(start=, goal=, heuristic=)`，分别是起始状态、自定义目标、自定义启发值。

## 规则模型里的假设（待在游戏里核对）

- 退出关卡时，恶魔出现在入口关卡块**初始位置**的旁边。因为退出时上一层已经先被重置了，所以按文本推断是这样，还没在游戏里确认。
