# 规则模型

`mdemon/sim.py` 实现单个关卡内的规则，`mdemon/world.py` 实现关卡之间的规则。规则来自各世界教程关的提示文字（中文版措辞最准确），并经过关卡数据和游戏内实测的核对。

## 单个关卡内（w1、w2）

- **推动**：恶魔可以推动一串方块；粘在一起的方块作为一个刚体移动；固定钉推不动；推不动时整次移动无效。
- **热交换**：每次移动之后，按导热面把物体连成导热分量（两边的面都不绝热才算连通）。每个分量取多数温度：热的份数多就全变热，冷的多就全变冷，一样多就变中性。碰到通向外界的窗口，就直接取外界温度。
- **恶魔**：导热但不储热；回合结束时如果是热的，就不能再动，也不能进入关卡。
- **过关**：回合结束时，目标格上有不透明方块，并且恶魔不烫。

已由关卡数据或游戏内实测确认：

- **热量按格计数**：多格方块有几格就算几份。依据是提示关 `cde27355`（按刚体计数时这关无解），以及 w1 第 12 关的实测解法（3 格冷块同时贴上 3 格热条，全部变中性）。
- **侧面码 0 是粘性面**（`w2/sticky-1`）：碰到任何面都会粘住，墙也算，之后作为一个刚体移动，不会再分开；粘性面导热，但碰上绝热面就不导热；恶魔不会被粘住。
- **透明块**（attr bit1 = 0）：不储热，热量份数为 0，压在目标格上不算过关。它带的温度只是当前导过来的，孤立时温度归零。

为了支持"只销毁一格"，可动的多格方块在模型里按格拆成单独的物体，由粘连分组连在一起；含有固定格的整块（比如墙体）仍然是一个物体。

## 关卡之间（w3）

**真关卡块和捷径**：flag 为 1 的关卡块是这个关卡的**真关卡块**，放在它的真实上一级关卡里，游戏里显示为"1"这样的编号；flag 为 0 的是**捷径**，显示为"3-1"这样的编号。游戏内实测：不管从哪种关卡块、从哪个方向进入，按 Q 退出时都会从真关卡块对应的那一侧出来。所以进入路径始终是**真实上级链**：进入关卡 X 后，路径就是从正在求解的关卡一路往下到 X 的真实上级链。原来就在路径上的层保持不变，中途跳过的层把这次进入的方向记作它们的进入方向。

搜索状态由这些部分组成：已解关卡集合；路径上每一层的关卡、外界温度、进入方向、入口关卡块；当前关卡的局面；中途离开、尚未重置的其他关卡的局面。

| 规则 | 实现 |
|---|---|
| exit-1 退出（解开或主动退出）时，所有关卡重置 | 退回下一层，那一层恢复初始局面，保存的局面全部清空 |
| exit-2「离开关卡的位置和进入时相同」 | 恶魔回到它（最后一次）进入时站的那一格，也就是真关卡块初始位置的进入侧 |
| enter-2 进入自己所在的关卡，局面延续 | 真实上级链不变，只更新这一层的进入方向和外界温度；恶魔回到起点 |
| 通过捷径进入路径上更低处的关卡（游戏内实测） | 路径截回到那个关卡的真实上级链 |
| enter-3 为了进入别的关卡而离开的关卡，在退出前保持局面 | 离开时保存它的局面，再进去时恢复 |
| transition-1 进出的那一刻不传热（游戏内实测） | 恶魔出现时完全不做热交换：恶魔贴着热块或冷块不会立刻变温，方块之间也不换热，全部留到下一次移动再结算 |
| transition-2 恶魔出现的位置上有方块，就把它销毁 | 进入和退出都会销毁，只销毁那一格。**墙格也会被销毁，带钉的也一样**（游戏内实测，`w3/path`）：被销毁的墙格变成一个洞，恶魔可以站进去，方块也能推进去；洞四周的墙面保持原样（大多是粘性面，所以推进去的方块会粘在墙上） |
| transition-3 进入时外界温度等于所进关卡块的温度；退出后，所在关卡的外界变中性 | 每层路径各记一个外界温度 |
| goal 解开关卡后立刻自动退出 | 走完那一步就退回下一层 |
| 被烫之后不能进入关卡（游戏内实测） | 恶魔是热的时候，不允许进入 |

有两条规则是根据游戏实测纠正过来的。最初我按英文提示把 exit-2 理解成"沿进入方向，从关卡块另一侧穿出来"，也让路径在循环进入时一直往下加层。后来在游戏里试了：提示关 → `1bfecdfb` → `b0e93052`，在后者里再进入前者，然后按 Q，结果直接退到了 `1bfecdfb` 外面。再结合中文提示，这两处都按实际行为改了。

有些关卡只能在特定上下文里解：要先解开别的关，或者要从冷/热关卡块进入，或者只会在上一级关卡里遇到。`Solver.solve(..., scope=上一级关卡)` 会从上一级关卡开始搜索，直到目标关卡被解开为止；`mdemon/context.py` 则从"刚通过真关卡块进入"的状态开始搜索。

## 活塞（w4）

实现在 `mdemon/sim.py`（`_move`、`_actuate`、`_turn`），规则测试在 `tests/test_sim.py` 的 `Pistons`。

**模型。** 按 w6 的提示「活塞本质上是一种带有'活动边'的方块」：活塞只占一格，朝箭头方向的那一面是活动边。
- 伸出的活塞就是一个普通方块，活动边位于格子边上。
- 收缩的活塞，活动边缩到格子后部，前面敞开，可以装下 1 个方块（内容）。内容的前面朝外，透过开口和前一格接触；后面贴着活动边；两侧是隔热的内壁，粘性面对内壁也有效。
- 文件里 state 的 bit0 为 1 表示伸出，为 0 表示收缩（可能带一个 slot 方块）。bit1–2 是方向：0 上、1 右、2 下、3 左。
- 局面里每个活塞记 `(是否伸出, 内容方块)`；内容方块和活塞的坐标相同。

**一轮结算。** 恶魔移动一步之后，进入热交换阶段。然后按编号从小到大，找第一个能动作的已触发活塞（收缩且热、或伸出且冷）。它的伸缩就是下一个步骤的"物体移动"，动作后变常温，再进行一次热交换，如此重复，直到没有活塞能动作为止（最多 64 步，超过就判为无效移动）。被挡住的活塞保持触发状态，不产生额外步骤。

| 规则 | 实现 | 依据 |
|---|---|---|
| 热的收缩活塞伸出 | 把内容推到前一格（可以连带推动一串方块）；推不动就让活塞自己往后退一格，内容留在原地；两边都不行就算被挡住 | 提示文字；"把内容推出去"在游戏里确认过 |
| 空的收缩活塞伸出 | 只改变状态，不推前面的方块 | 游戏内确认 |
| 冷的伸出活塞收缩 | 和活动边粘住的方块（任一面是粘性）被拉进活塞；拉不动就让活塞往前移一格把它套住；固定方块、多格方块和活塞拉不进来 | 提示文字；"把粘住的方块拉进来"在游戏里确认过 |
| 没有粘住任何东西的伸出活塞收缩 | 只改变状态 | 推断 |
| 被动：方块从正面推进伸出的活塞 | 方块进入活塞，活塞变成收缩，温度 +1（常温变热） | piston-passive-1 |
| 被动：和活动边粘住的内容被拉出去 | 活塞变成伸出，温度 −1（常温变冷） | piston-passive-2 |
| 活塞被往正面方向推，前面的方块（粘着或没粘）推不动 | 活塞滑过去把那个方块套进来，变成收缩；原来是伸出的，温度 +1 | 游戏内确认（w4 第 3 关的提示关：把冷块推到透明块左边，从上面推活塞，冷热抵消） |
| 方块从正面推进空的收缩活塞 | 方块进入，温度不变 | 推断（w6 的"存放"） |
| 拖动 | 活塞带着内容一起移动；粘在活动边上的方块横向拖动时，活塞跟着动；沿伸缩方向推拉时，活塞改为伸缩 | 推断 |
| 透明活塞 | 被动伸缩不改变温度 | w6/piston-empty |
| 热交换 | 收缩活塞的正面不和外面接触；内容透过开口和前一格换热，透过活动边和活塞本体换热（两面都不隔热时）；内壁隔热 | w6 提示 |
| 恶魔 | 不能进入活塞；推空的收缩活塞的开口时，整个活塞被推走；活塞伸缩时，恶魔所在的格子算作障碍 | 推断 |

求解器在有活塞的关卡里不用推动距离表（启发值恒为 1），也不做同类方块的对称去重。还有活塞处于触发状态时，不把恶魔的行走折叠成一步，因为恶魔走开后，被它挡住的活塞可能会动作。

## 还没在游戏里确认的假设

- 退出时恶魔出现在真关卡块**初始位置**的旁边。退出时上一层已经先被重置了，所以按文本推断应该是这样。
- 恶魔同时贴着多个关卡块时，求解器允许任选一个进入（游戏里进的是编号最小的那个）。
- 恶魔不会出现在网格外面：遇到这种情况，就判定为不能进出。
- 活塞：表里标"推断"的各条；还有压缩一个冷的伸出活塞时，温度按 +1 算，变成常温。
- 活塞：两个活塞同时伸缩时，"最稳定的优先"（w8）还没有实现，现在只按编号排序。
