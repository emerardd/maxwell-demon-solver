# 搜索方法

## A* 求解器（mdemon/solver.py）

- 在整个嵌套状态上做 A* 搜索（状态见 [rules.md](rules.md)）。每一步是一个"宏步"：一次推动、一次会改变温度的走步、一次进入，或一次退出。
- **热惰性走步折叠**：恶魔会导热，所以只有不改变任何温度的走步才能折叠，也就是每个导热邻居的温度都相同、且都不是热的，并且关卡已处于热平衡。通过这种走步能到达的格子，算作同一个恶魔位置，用其中最小的格子代表。
- **相同方块去重**：形状、侧面、透明度都相同，又没有粘连的可动方块，互换位置视为同一状态（`sim.Model.symmetric_key`）。
- **路径深度迭代加深**：先只允许 2 层嵌套，再放宽到 3、4、6 层；如果深度上限从来没挡住过任何一次进入，就直接判定无解。
- 时间预算、加权 A*（`h_weight`），以及三个钩子 `solve(start=, goal=, heuristic=)`：起始状态、自定义目标、自定义启发值。
- `solve_any`：先跑引导式搜索（权重 3），超时后再用最短解 A*。单元测试和攻略生成都用它。

## 剪枝（mdemon/prune.py）

在只保留墙体和固定方块的静态关卡里，从目标格反向 BFS，算出每个可动的粘连分组从各个位置最少要推几次，才能把它的一个不透明格压上目标。

- 作为 A* 的启发值。它忽略其他方块和温度，所以是可采纳的。
- 所有分组都到不了目标时，直接判死。
- 分组会变：粘连会合并分组，销毁会拆开分组。成员和初始时完全一样的分组用自己的距离表；变过的分组改用宽松的逐格距离表（只要求沿空格可达）。
- 关卡里有能粘上新东西的粘性面时，分组的距离表也改用宽松算法（`w2/sticky-1` 就是这种情况）。
- 已经粘死在墙上、又不在目标上的分组，不再算作候选。
- 关卡里有关卡块时，启发值最多取 1：进出关卡会重置局面，解开关卡还会改变关卡块的属性，这些距离表都算不到。

## 引导式搜索（不求最短解）

难关的开销全花在"不同的方块布局"上（`scripts/search_stats.py`）：恶魔位置折叠后，每种布局平均只剩约 1 个恶魔位置，但每多推一步，布局数就要乘约 5 倍。可靠的剪枝最多只能省常数倍，所以在不需要最短解的场合，改用 `heuristic='informed'`（`Pruner.informed`，不可采纳）。对每个候选方块，取它沿距离表到目标要推几次，再加上：

- 路线上每有一个挡路的可动方块，加一份罚分；
- 推动后恶魔站的位置如果会贴到热块的导热面（包括候选方块自己），就算一个"危险源"，每个危险源加罚分，再加上冷却代价：
  - 已经是冷的方块，按它到危险源的距离计；
  - 能冻成冷的中性导热块，按"它到冷源的距离 + 冷源到危险源的距离 + 冻结代价"计；
  - 冷的份数不够抵消热时，再加罚分。

小规模对比的结果（`scripts/bench.py`）：`eadb3d02` 从超时降到 2 秒解出，`0f029258` 也能解出了。

## 分阶段子目标搜索（mdemon/staged.py）

腾挪关必须先把最后几步的布局定下来，否则正向搜索只会在海量布局里打转。`StagedSearch` 按顺序给出若干中间布局（某个方块要到哪一格、是否必须是冷的），逐阶段求解，最后接着搜到过关。

- 每个阶段都要保持前面阶段已经达成的部分，每次只再多放一块。
- 启发值用各方块到目标格的**推动距离**：反向搜索，并要求每一推的身后都有恶魔能站的格子；推进死角的方块，距离为无穷大。
- 还没冻冷的方块，要绕道去一个冻冷点，而且这个点必须推得进去、也推得出来。冻冷点包括"恶魔站在中间当中转"的情况：恶魔导热但不储热。
- 后面阶段要用的方块，一旦被推到再也到不了目标的位置，就直接剪掉。

```bash
python -u scripts/subgoal.py "<游戏目录>" 4b1153be 30 6@8,2:C / 2@7,2:C / 3@8,3:C / 5@7,3:C
```

## 自动推导终局布局和阶段顺序（mdemon/derive.py）

把手工推导腾挪关的过程变成算法，从终点往回推：

1. **最后几推**：找出离目标最近（按推动距离）的候选方块，以及把它推上目标时恶魔要站的格子。
2. **危险源**：在这些格子上，会通过导热面烫到恶魔的热块组。
3. **冷却布局（小规模约束搜索）**：在危险源旁边选一个桥接格，恶魔站在那里，就能把危险源和一组冷块连成一个导热分量。从桥接格出发，按"两面都导热"逐块往外接方块，直到冷的份数不少于热的份数。约束如下：
   - 方块不能直接贴着危险源；
   - 不能占用最终路线和恶魔要站的格子；
   - 每块都要能推到自己的格子；
   - 摆好之后，恶魔还要能走到桥接格和最后的推动位置。
4. **阶段顺序**：把已经放好的块当成墙，逐个检查每一块能否先被冻冷、再推到位。
5. 把布局和顺序交给分阶段子目标搜索执行；不行就换下一个顺序或下一个布局。

```bash
python -u scripts/derive.py "<游戏目录>" 4b1153be 30 --out solutions/w1-15_4b1153be_auto.txt
```

在 w1 第 15 关上，它 2.8 秒就自动得出了和人工完全相同的方案（66 步，在游戏里实测可行）。目前只处理"最后几推被一个热块组挡住、要用冷块去抵消"这一类，参与冷却的方块也只考虑单格方块。
